# kDrive Arch 3.8.7.1-18 implementation plan

## Goal

Ship `kdrive-arch` `3.8.7.1-18` with a reliable Arch-family update path,
systemd-owned runtime, no duplicate installers in the runtime payload, and
release assets built and attested by CI.

## Global constraints

- Preserve the existing `kdrive-native-arch` migration and rollback contract.
- Do not touch `/usr/share/omarchy` or kDrive account/sync data.
- Keep the public install command release-name independent.
- Keep Sentry activation disabled; do not claim zero telemetry without a test.
- Source remains official desktop-kDrive commit `b14222be555cc9f934e9ed2ec7bb36beb9c437a5`.
- Runtime remains `RelWithDebInfo`, stripped of static archives, headers, and
  debug sections; debug symbols remain a separate asset.
- Default build staging must not use XDG cache semantics. Use an explicit
  caller override and a `/var/tmp` default with free-space/filesystem checks.

## Tasks

### Task 1: Installer lifecycle and staging

Modify `install.sh` and `tests/test-installer-redteam.sh` to:

- build/download before mutating user overrides;
- select `KDRIVE_BUILD_ROOT` when set, otherwise `/var/tmp/kdrive-arch`;
- create a private `mktemp` directory and fail before state mutation when the
  root is not writable, local, or has insufficient free space;
- capture active/enabled state, stop an active service before package removal or
  installation, and explicitly restart/start after `daemon-reload`;
- verify the service's real `/proc/$MainPID/exe` resolves under `/opt/kdrive-arch`;
- preserve rollback on failed install or failed restart;
- add active-service fixtures proving the old process cannot survive an update.

### Task 2: Runtime/package contract

Modify `build/build-package.sh`, `PKGBUILD`, `tests/check-package.sh`,
`tests/test-build-output-contract.sh`, `tests/test-package-name-contract.sh`,
and documentation to remove `kdrive-install.sh` and the duplicate internal
unit from the runtime bundle. The package-owned `/usr/bin/kdrive-arch` and
`/usr/lib/systemd/user/kdrive.service` remain the only launch path.

### Task 3: Release CI/CD

Modify `.github/workflows/release-arch.yml` and supporting docs/tests to build
the Arch package and debug bundle in an Arch container, publish the package,
debug symbols, source archive, installer, and checksums, and create a GitHub
artifact attestation. Keep the release tag/package identity check and ensure
the release asset names are deterministic for `3.8.7.1-18`.

### Task 4: Integration and release

- bump `pkgrel` and regenerate `.SRCINFO`;
- run shell syntax, repository/package contracts, red-team tests, and CI-equivalent
  checks;
- build the package in an Arch environment and inspect package contents;
- publish tag `kdrive-arch-3.8.7.1-18` only after all checks pass;
- install the published release on this Omarchy host, verify real process,
  user unit, journal connection, coredump absence, and rollback pointers;
- retain local `0600` telemetry and do not transmit it.

## Acceptance criteria

- Active update produces a new PID and `/proc/$pid/exe` under `/opt/kdrive-arch`.
- Failed build/transaction/restart restores prior package and service state.
- Runtime package contains no `.a`, public headers, internal installer, or
  duplicate unit; no debug sections remain in shipped binaries.
- Release contains package, debug bundle, source, installer, checksum, and
  CI attestation.
- Public latest-release install, verify, and rollback paths remain usable.
